# Phase 6A bounded performance checkpoint

SQL/RUNTIME synthetic local PostgreSQL 17 only; not hosted HTTP latency or a
production capacity claim. A 2,000-contribution, wide finite component benchmark
passed at 390.493ms in the final full run (392.269ms in the final focused run) with the fixed eight-second test
budget. The benchmark also checks the joint complete Volleyball hitting cohort.
Canonical sealed-source lifecycles and all six engine adapter tests run separately.

Dashboard reads refresh at most eight dirty source games and disclose pending
without totals if bounded refresh cannot complete. Clean projections read origin
summaries, not replay a player's raw career. At most 100 origin segments are
returned; a larger projection returns pending/bounded-report state. Eager refresh
is limited to frozen rosters of at most 50 and reductions at most 2,000 eligible
origin contributions. Existing statement timeout is unchanged.

Explicit authorized rebuild is resumable by an exact scoped game cursor, one
canonical source per batch in event/game lock order, and can reconstruct origins
beyond the eager threshold under existing execution limits. Call successive
batches until rebuild_complete. Immutable source epochs/contributions remain.
A contested origin advisory lock returns pending instead of waiting while
retaining game locks; failed/bounded refresh does not certify a generation current.

No artificial production scale, benchmark records or acceptance window exists.
Multi-season/transfer/refinalization and cross-sport provenance are covered by
canonical lifecycle/source tests; broader synthetic scale/hosted latency remains
to be finalized before full release completion.
